# 第1章 ツールの概要

## 1.1 これは何をするツールか

**VA mints**は、民事裁判書類電子提出システム「mints」の「記録」への提出前に、フォルダ単位でファイル群の内容を確認し、mintsの制約（用紙サイズ・ファイル名・パスワードの有無・証拠番号標記等）に適合しているかを一括してチェックするためのツールです。

このツールは、**チェック（検出・警告）に専念する**という設計方針を採っています。用紙サイズの補正やファイル形式の変換、OCRの付与といった「原本の中身を作り替える」機能はあえて実装していません。問題が見つかった場合は、Word・Excel・PDF編集ソフトなど普段お使いのアプリケーションで修正していただき、修正後のファイルを本ツールに再度読み込んで再検証する、という使い方を想定しています。

これは機能不足ではなく意図的な設計です。証拠として提出する文書は、内容の変更それ自体が証拠価値の評価に影響しかねません。「技術的に情報を失わない処理だから自動実行してよい」という判断は、本ツールでは採用していません。ファイルの中身を変える処理（証拠番号スタンプ、ファイル名整形、メタデータ除去、枝番ファイルの結合、向き補正）は、ファイルごとに、行う処理をチェックボックスで選び、プレビューで結果を確かめられるようになっています。実際にファイルを更新するのは、「ファイルを更新」を押し、処理ごとの件数を示した確認に「OK」と答えたときだけです。更新する前のファイルは、同じフォルダの中の「元のファイル」フォルダに残り、「元のファイルに戻す」でいつでも元に戻せます。

## 1.2 できること・できないこと

**できること（検出・警告）**

- フォルダ内の全ファイルのスキャンと状態把握（形式・サイズ・分類）
- ファイル名の制約の検出（100文字超過・禁止文字・JIS X 0213外の文字の可能性）
- 単体ファイルの200MB超過検出（合計サイズとは別の重大警告）
- パスワード付きPDFの検出
- 操作制限（印刷・コピー制限）PDFの検出
- 用紙サイズ（A4／A3以外）・向きの不一致検出
- 墨消し完全性の検証（黒塗り・マーカー下の文字情報の残存検出）
- 号証の連番・欠番チェック
- 個人情報らしきパターン（マイナンバー・電話番号・メールアドレス・住所・銀行口座・クレジットカード番号等）の検出

**できること（チェックボックスで選び、確認のうえで実行する処理）**

- ファイル名整形（100文字以内への調整、禁止文字の除去）
- メタデータ除去（作成者情報、Exif位置情報等）
- 200MB単位の仕分け（複数回提出のための事前仕分け。「提出用_01」等のサブフォルダを自動で作り、ファイルを移します）
- 更新したファイルを、更新する前の状態に戻す（「元のファイルに戻す」）
- 証拠番号（甲001等）の右上スタンプ（**スタンプする番号は、ファイル名の先頭に付けられた証拠番号からそのまま決まります**〔詳細は3.2節参照〕。位置調整可能）
- 枝番ファイルの結合
- 向き補正（向きが基本形〔A4=縦・A3=横〕と不一致のページの90°回転。PDFの回転属性のみの変更で、ページの内容・画質・テキストは変わりません）

**できないこと（意図的に実装していない機能）**

- ファイル形式の変換（DOCX/XLSX/PPTX→PDF、TIFF等→JPEG/PNG、動画・音声形式の変換）
- OCRによるテキストレイヤーの付与・削除
- 用紙サイズの自動補正（拡大縮小配置）
- 墨消し漏れの自動修復（検出・警告のみ）
- 無彩色画像のグレースケール変換
- ファイルの分割・圧縮によるサイズ削減

これらが必要な場合は、他の専用ソフトで対処したうえで、本ツールに再度読み込んで再検証してください。

## 1.3 安全性に関する設計方針

- **完全ローカル動作**：いかなる処理段階でも外部ネットワーク通信を行いません。クラウドAPI・外部OCRサービス・外部変換サービス・利用状況の送信・自動アップデート確認、いずれも実装していません。証拠・準備書面等の内容が、お使いのパソコンの外部に送信されることはありません。
- **生成AI（LLM等）を使用しない**：検出処理はすべて正規表現やライブラリによる機械的な判定であり、生成AIによる文字起こしや要約は行いません。
- **更新する前のファイルを必ず残す**：Ver.200から、読み込んだフォルダの中のファイルを、その場で更新する方式になりました。更新する前のファイルは、同じフォルダの中に作られる「元のファイル」フォルダに残ります。「元のファイルに戻す」で、更新する前の状態（名前・位置・内容）に戻せます。更新は、確認の画面で「OK」と答えたときにだけ行われます。

# 第2章 導入方法

## 2.1 配布物の構成

本ツールは、次のファイル一式で構成されています。

| ファイル | 内容 |
|---|---|
| `VA_mints.exe` | 実行ファイル本体（Python環境不要） |
| `config.yaml` | 数値パラメータ等の設定ファイル（テキストエディタで編集可能） |
| `LICENSE` | ライセンス条文（MIT License） |
| マニュアル（フォルダ） | 本マニュアル（PDF） |
| `source/` | ソースコード一式（Python。改変・再配布はライセンス条件の範囲内で自由） |

## 2.2 起動方法

1. `VA_mints.exe` と `config.yaml` を、**同じフォルダ内**に置いてください（config.yamlは実行ファイルに内蔵されておらず、外部ファイルとして読み込む仕組みのため、必ず同じフォルダに置く必要があります）。
2. `VA_mints.exe` をダブルクリックして起動します。Python環境のインストールは不要です。
3. Windows Defender SmartScreen等により警告が表示される場合がありますが、これは未署名の実行ファイルに一般的に表示されるものです。内容にご不安がある場合は、`source/` フォルダ内のソースコードをご確認いただくか、ご自身の環境でビルドし直してご利用ください。

## 2.3 動作環境

Windows環境を想定しています（法律事務所の一般的なPC環境に合わせています）。

Macでは、ソースコード（`source/` フォルダ。GitHubのVBA-Assets/VA_MINTSでも公開しています）から、Python 3で動かすことができます（**動作は保証しません**。Mac用の実行ファイルは配布していません）。手順は次のとおりです（ターミナルで `source/` フォルダに移動してから実行します）。

1. `python3 -m pip install -r requirements.txt`
2. `python3 main.py`

Macで動かす場合、Windowsと次の点が異なります。

- 画像（JPEG・PNG）に焼き込む証拠番号の書体は、Mac標準のヒラギノ角ゴシックになります（Windowsではメイリオ）。字の形だけが異なります。PDFに焼き込む証拠番号はWindowsと同じです。
- 完了ダイアログの「フォルダを開く」は、Finderで更新したフォルダを開きます。
- Macのファイル名は、濁点・半濁点を分けた形で保存されていることがあります。文字数・JIS X 0213外の文字の判定は、濁点・半濁点を合わせた形で行います。

# 第3章 基本的な使い方

## 3.1 画面の構成と、ファイルの読み込み

画面上部の操作は、Wordなどと同じ**リボン**の形にまとまっています。ボタンは「読み込み」「更新」の2つの組に分かれ、組の名前が下に小さく表示されます。各ボタンや欄にマウスを重ねると、少し間をおいて説明書きが表示されます。

リボンの3つのボタン（「ファイルを読み込み」「ファイルを更新」「元のファイルに戻す」）と同じ操作は、画面上部の**［ファイル］メニュー**からも行えます（押せる・押せないは、リボンのボタンと同じです）。［ファイル］メニューの**［オプション］**では、証拠番号スタンプの文字の大きさを変えられます（3.3参照）。

リボンの下は、**3つのペイン（区画）**に分かれています。ペインの境目は、左右にドラッグして幅を変えられます。

| ペイン | 表示されるもの |
|---|---|
| 左 | 読み込んだファイルの名前の一覧 |
| 中央 | 左で選んだファイルのプレビュー（右端のスクロールバーでページを送ります） |
| 右 | 処理の項目（チェックボックス）。左で選んだファイルに適用するものにチェックが付きます |

起動後、まず「読み込み」の組で入力フォルダ（チェック対象のファイルが入っているフォルダ）を選択します。フォルダ欄の右にある「...」ボタンから参照ダイアログで選ぶこともできます。Ver.200から、出力フォルダはありません（読み込んだフォルダの中のファイルを、その場で更新します）。

入力フォルダ欄の下には**「サブフォルダ内のファイルも含める」**のチェックボックスがあります。既定はOFF（入力フォルダ直下のファイルのみが対象）です。ONにすると、サブフォルダの中のファイルもまとめて読み込まれます。他の事件の書類などが混在するフォルダで意図しないファイルまで読み込んでしまわないよう、必要な場合のみONにしてください。なお、このチェックにかかわらず、「元のファイル」フォルダ（3.4参照）の中は読み込まれず、「提出用_01」等のフォルダ（3.5参照）の中は読み込まれます。

「ファイルを読み込み」を押すと、対象フォルダ内の全ファイルが自動的にスキャンされ、左のペインに一覧表示されます。読み込みではファイルは変更されません。OSやアプリケーションが自動生成する一時ファイル（Thumbs.db、desktop.ini、Officeの作業ファイル〔~$で始まるもの〕、.tmpファイル）は、提出対象になり得ないため読み込み対象から自動的に除外されます。

左のペインの一覧には、ファイル名だけが表示されます。行は、検出の結果に応じて色分けされます。

| 行の色 | 意味 |
|---|---|
| 薄い緑 | 適合済み（検出できる要対処事項がない） |
| 薄いオレンジ | 要修正（ファイル名・メタデータ・パスワード・用紙寸法など、何かが検出された） |
| 薄い青 | 要変換（Wordなど、mints「記録」の対応形式ではない。PDF等に変換してから読み込み直す） |
| 灰色 | 対象外（未対応の形式、拡張子と中身の不一致など） |

**号証の連番・欠番・重複の疑い**（甲002が欠けている等）があるときは、一覧の下に赤字で表示されます（複数のファイルにまたがる検出結果のため、ここにまとめて表示します）。

**「ファイルを更新」のボタンは、ファイルを読み込むまでは押せません**（灰色の表示になっています）。読み込みが済むと押せるようになります。

## 3.2 ファイル名と証拠番号の扱い

本ツールには、ファイル名を編集する機能はありません。ファイル名は、あらかじめエクスプローラー等で適切に付けたうえで読み込んでください（ツールはファイルの中身の適否からファイル名を判断できないため、意図的にこの設計としています）。

読み込んだファイル名の**先頭**が証拠番号の形式に合致すると、そのファイルは証拠番号処理（右上スタンプ・枝番結合等）の対象候補として扱われ、右のペインの処理の項目に「証拠番号スタンプ」「枝番ファイル結合」が表示されます。証拠番号の形式に合致しない場合（準備書面・証拠説明書等と推定される場合）は、証拠番号処理は適用されません。証拠番号の書き方は次のとおりです。

- **ファイル名の一番先頭に置いてください。** 途中や末尾にある場合は認識されません（`20260726 甲001 売買契約書.pdf`や`売買契約書 甲001.pdf`は認識されません）。
- **符号＋半角3桁の数字**が基本形です（符号は甲・乙・丙。例：`甲001`）。数字は3桁ちょうどが必要で、桁数が異なる書き方（`甲1`等）は認識されません。
- **被告が複数などで添字が必要な場合**は、符号の直後に半角英字を1文字加えます（例：`乙A001`）。
- **枝番のある複数ファイルを1つに結合したい場合**は、証拠番号の後ろに「-」（半角ハイフン）又は「_」（アンダースコア）で区切って枝番の数字を続けます（例：`甲001-1`、`甲001_1`）。結合対象になるのは、同じ証拠番号で枝番だけが異なる2件以上のファイルです。
- 既に1ファイルへまとめてあり、範囲（例：1〜20号証）をファイル名に表記したい場合は、枝番の後ろに「~」（半角チルダ）で区切って終端の枝番を続けます（例：`甲001-1~20`）。この表記のファイルは既に結合済みとみなされ、結合候補には含まれません。
- 証拠番号（枝番を含む）より後ろの部分は「標目」として自由に付けられます。一次資料の例（「甲001 売買契約書原本」）に合わせ、証拠番号との間に半角スペースを1つ入れる書き方を推奨します。

証拠番号スタンプに実際に使われる番号は、この先頭部分（符号・添字・数字・枝番）から自動的に決まります。枝番ファイルを結合する場合、結合後のファイル名も、代表となるファイル（最小の枝番）の証拠番号・区切り文字・標目をそのまま踏襲して自動生成されます（例：`甲001-1 領収書A.pdf`と`甲001-2 領収書B.pdf`を結合すると`甲001-1~2 領収書A.pdf`になります）。

なお、ファイル名がmintsの制約に技術的に反する場合（100文字超過・禁止文字）の整形は、右のペインの処理の項目（3.3参照）で選べます。号証の連番・欠番・重複はチェック機能が検出・警告しますので、必要な改名はエクスプローラー等で行い、再度読み込んで確認してください。

## 3.3 処理の項目とプレビュー

右のペインには、**処理の項目**（ファイル名整形・メタデータ除去・向き補正・証拠番号スタンプ・枝番ファイル結合）が、いつも同じ並びで表示されています。左のペインでファイルを選ぶと、中央のペインにそのファイルのプレビューが表示され、右のペインでは、**そのファイルに適用する項目にチェックが付きます**。そのファイルに当てはまらない項目（メタデータのないファイルの「メタデータ除去」など）は、灰色の表示になり、チェックできません。

**右のペイン（処理の項目）**

- **本ツールでは対処できない検出結果**（パスワード・操作制限・用紙寸法・墨消し残存の疑い・個人情報らしきパターン・単体200MB超過）は、検出されたときに、**処理の項目の上に赤字で表示**されます。これらは他のアプリで対処のうえ、本ツールに再度読み込んで再検証してください。
- **本ツールで実行できる処理**の項目のうち、そのファイルに当てはまるものには、処理の内容（整形後のファイル名、検出されたメタデータの項目、スタンプする番号など）が書かれます。**必要と判断された項目には、読み込んだときにチェックが自動で付いています。** チェックは個別に付け外しできます。チェックを外した処理は行われません。
- 自動でチェックが付くのは、ファイル名整形（100文字超過・禁止文字があるとき）、メタデータ除去（メタデータが検出されたとき）、PDFの証拠番号スタンプ、枝番ファイル結合です。**画像（JPEG・PNG）の証拠番号スタンプと向き補正は、チェックできる状態になりますが、自動ではチェックが付きません**（写真などは見た目そのものが証拠の内容になり得ること、文書がどちらを向いているかはツールには判別できないことから、個別にご判断いただくためです）。
- **向き補正**：向きが基本形（A4=縦・A3=横）と不一致のページが検出されたPDFに表示されます。回転はPDFの回転属性のみの変更で、ページの内容・画質・テキストは変わりません。チェックを入れるとプレビューが回転後の見た目に切り替わるので、読める向きになることを確認してください。回転方向は「左に90°／右に90°」から選べます（既定は左に90°）。
- **証拠番号スタンプ**：PDFの**1ページ目の右上だけ**に押します（2ページ目以降には押しません）。文字の大きさは、既定で**16ポイント**（字の高さ約5.6mm。紙の「甲第　号証」のゴム印の字とほぼ同じ大きさ）です。［ファイル］→［オプション］で、8〜36ポイントの間で変えられます。変えた大きさは、パソコンのユーザーごとに保存され、次に起動したときも使われます（［既定に戻す］で16ポイントに戻ります）。すでにスタンプを付けたファイルの大きさは変わりません。チェックがあると、項目の下の上下左右ボタンで焼き込み位置を微調整できます（動かした位置は、そのファイルだけに使われます。スタンプは向き補正後の右上に載ります）。
- **枝番ファイル結合**：同じ証拠番号で枝番だけが異なるPDFが2件以上あるとき、そのどのファイルを選んでも、同じ1つのチェックが表示されます（結合するすべてのファイルで共通です）。チェックがある間は、結合後のファイルについての項目（枝番ラベルのスタンプ等）が表示されます。チェックを外すと結合は行われず、そのファイルだけの項目に切り替わります。
- 要変換・対象外のファイル（行の色が薄い青・灰色）は、処理の項目がすべて灰色になり、何をすればよいかの案内が赤字で表示されます。これらのファイルは更新されません。

**中央のペイン（プレビュー）**

- プレビューは、**右のペインでチェックの付いている処理を行った後の状態**を表示します。チェックを付け外しすると、プレビューもその場で描き直されます（証拠番号スタンプ・向き補正）。
- 複数ページのPDFは、プレビューの右端の**スクロールバー**（又はマウスのホイール）でページを送って、全ページを確認できます（1ページずつ表示されます。右下に、いま何ページ目かが表示されます）。**原本に証拠番号が既に記載されていないか（重複スタンプの防止）は、1ページ目だけでなく全ページを確認したうえで判断してください。** 結合するファイルは、左のペインで1つずつ選んで確認してください（スタンプは、結合するそれぞれのファイルの1ページ目に、その枝番で載ります）。
- 画像（JPEG・PNG）は、小さいものも、プレビューの枠いっぱいの大きさに拡大して表示されます（表示だけで、ファイルは変わりません）。
- パスワード付きファイル、音声・動画ファイルなど、プレビューを表示できないファイルには、その旨が表示されます。

## 3.4 ファイルの更新と、元のファイルに戻す操作

**ファイルを更新**

「ファイルを更新」を押すと、**読み込んだすべてのファイル**が、それぞれの処理の項目のチェックのとおりに更新されます（左のペインで選んでいるファイルだけではありません）。

押すと、まず確認の画面が表示されます。確認の画面には、処理ごとの件数（ファイル名整形○件、メタデータ除去○件、証拠番号スタンプ○件など）と、**内容を変えるファイルのうち、まだプレビューを表示していないファイルの数**が示されます。証拠番号スタンプを付けられるのにチェックの入っていない画像（JPEG・PNG）があるときは、**「証拠番号スタンプを付けない画像：○件」**の行も示されます（画像のスタンプは自動ではチェックが付かないため、付け忘れがないかをここで確かめられます。チェックを外したまま一度更新した画像は、次からは数えられません）。まだ表示していないファイルがあるときは、いったん「キャンセル」を選び、左のペインでそのファイルを選んで、プレビューと処理の項目を確かめてから更新することをお勧めします。「OK」を選ぶと更新が始まります。

個別のファイルの更新に失敗した場合（そのファイルを他のアプリで開いている等）は、エラー内容とともに「この1件をとばして続けるか、残りを中止するか」を選択できます。失敗したファイルは、更新する前のままです。更新できなかったファイルは、完了時のダイアログに、名前と理由が並びます（3.6参照）。

**「元のファイル」フォルダ**

更新する前のファイルは、読み込んだフォルダの中に作られる**「元のファイル」フォルダ**に、そのまま残されます。

- 「元のファイル」フォルダに同じファイルが既にあるときは、保存されません。つまり、同じファイルを2回、3回と更新しても、「元のファイル」フォルダに残るのは、**最初に更新する前のファイル**です。
- 最初の更新の後にフォルダへ足したファイルは、そのファイルを初めて更新するときに保存されます。
- 「元のファイル」フォルダには、ほかに、更新の記録（更新記録.json。どのファイルにどの処理をしたか）が置かれます。**このフォルダの中のファイルは、名前を変えたり動かしたりしないでください**（「元のファイルに戻す」ができなくなります）。
- 「元のファイル」フォルダは、mintsに提出するものではありません。本ツールも、このフォルダの中は読み込みません。

**更新の後**

更新が済むと、フォルダが自動で読み込み直されます。**処理の済んだ項目のチェックは外れます**（メタデータ除去など。済んだ処理は、もう検出されないためです）。

**証拠番号スタンプだけは、扱いが異なります。** 更新の後は、チェックが「スタンプが付いているかどうか」を表します。

- **スタンプを付けたファイルは、チェックの入った状態で表示されます。** チェックを入れたままなら、もう一度更新しても何も起きません（スタンプが二重になることはありません）。
- **チェックを外して「ファイルを更新」を押すと、スタンプが消えます。** チェックを外した時点で、プレビューがスタンプのない状態に切り替わります。スタンプを消すときは、「元のファイル」フォルダに残っている更新する前のファイルから、スタンプ以外の済んだ処理（メタデータ除去など）だけをやり直して作り直します。そのため、**更新の後に他のアプリでそのファイルを直していた場合、その内容は失われます**（更新の確認の画面に「証拠番号スタンプの消去：○件」と表示されます）。
- スタンプのチェックを外して更新したファイルには、読み込み直しても、自動でチェックが付くことはありません（次の更新で、意図せずスタンプが付くのを防ぐためです）。付けたくなったら、チェックを入れて更新してください。
- スタンプを付けたファイルには、位置調整のボタンは表示されません。位置を変えたいときは、いったんチェックを外して更新し、チェックを入れ直して位置を調整してから、もう一度更新してください。

**元のファイルに戻す**

「元のファイルに戻す」を押すと、本ツールで更新したすべてのファイルが、「元のファイル」フォルダに残っている、更新する前のファイルに戻ります。名前を変えたファイル、結合したファイル、「提出用_01」等へ移したファイルも、元の名前・元の位置に戻ります。戻した後はフォルダが読み込み直され、処理の項目のチェックは、再び自動で付きます。

- **更新の後に、他のアプリでそのファイルを直していた場合、その内容は失われます**（更新する前のファイルに置き換わるためです）。押すと確認の画面が出ますので、確かめてから「OK」を選んでください。
- 戻す先に、更新の後で置かれた同じ名前の別のファイルがあるときは、上書きせず、その1件だけを戻さずにお知らせします（更新する前のファイルは「元のファイル」フォルダに残ります）。
- すべてのファイルを戻すと、「元のファイル」フォルダはなくなります。
- このボタンは、読み込んだフォルダに、本ツールで更新したファイルがあるときだけ押せます。

## 3.5 200MBを超える場合の扱い

合計サイズが200MB（既定の安全マージン90％＝180MB）を超える場合、「ファイルを更新」のときに、読み込んだフォルダの直下に「提出用_01」「提出用_02」…という提出回ごとのサブフォルダが自動で作られ、ファイルがそこへ移されます（更新の確認の画面に、その旨と件数が示されます）。1回の提出で収まる場合は、サブフォルダは作られず、ファイルは元の位置のままです。完了時には、何回に分けて提出するかが表示されます。各サブフォルダの中身を、提出回ごとにmintsへアップロードしてください。

内容を変えずに移されるだけのファイルは、「元のファイル」フォルダには写されません（移した元の位置だけが記録され、「元のファイルに戻す」で元の位置に戻ります）。

なお、**単体で200MBを超えるファイル**が検出された場合は、複数回に分けても解決しない重大な警告として、右のペインと更新の確認の画面に表示されます（圧縮・分割の実行機能はないため、他のツールで対処してください）。

## 3.6 完了時の確認

更新が済むと、更新した件数を示すダイアログが表示されます。

- **更新できなかったファイルがあるとき**は、その名前と理由（他のアプリで開いている可能性がある、等）が並びます。それらのファイルは、更新する前のままです。原因を取り除いてから、もう一度「ファイルを更新」を押してください（更新が済んだファイルは、チェックが外れているので、二重には処理されません）。
- 複数回に分けて提出する必要があるときは、「提出用_01」等のフォルダごとの件数が表示されます（3.5参照）。
- **「OK」と「フォルダを開く」の2つのボタン**があり、後者を選ぶとダイアログを閉じると同時に、更新したフォルダがエクスプローラーで開きます。

Ver.170まで出力していたレポート（mints提出前レポート.txt）は、Ver.200で廃止しました。検出結果は、ファイルを選んだときの右のペイン（3.3参照）と、画面下部の号証の連番・欠番の表示（3.1参照）で確認できます。どのファイルにどの処理をしたかは、「元のファイル」フォルダの更新の記録に残り、更新する前のファイルも同じフォルダに残ります。

## 3.7 ヘルプメニューと診断情報

画面上部のメニューは、［ファイル］（3.1参照）と［ヘルプ］の2つです。［ヘルプ］メニューから、次の操作ができます。

- **診断情報をコピー**：ツールの版・OS・設定の数値・読み込んだ件数・起きたエラーの型と場所（ファイル名・行・関数名）だけをまとめた文を、クリップボードにコピーします。**証拠・書面のファイル名、ファイルやフォルダの場所、エラーメッセージの本文など、事件の内容につながる情報は含まれません。** 不具合をAIや作成者に相談するときは、この診断情報を使ってください（中身は入りません）。渡す前に、メモ帳などに貼り付けて内容を確かめることもできます。
- **VA mints について**：ツールの名前と版を表示します。

# 第4章 設定ファイル（config.yaml）

`config.yaml` では、数値パラメータ等をハードコードせず一元管理しています。テキストエディタで開いて編集できます。主な項目は次のとおりです。

| セクション | 主な項目 | 内容 |
|---|---|---|
| `upload` | `max_total_mb`、`safety_margin_ratio` | 1回のアップロード合計上限（既定200MB）と分割時の安全マージン（既定90％） |
| `evidence_number` | `symbols`、`digits` | 証拠番号の符号（甲・乙・丙）と桁数 |
| `filename` | `max_length`、`warning_length`、`forbidden_chars` | ファイル名の上限文字数（既定100）・警告閾値（既定50）・禁止文字 |
| `evidence_stamp` | `font_size_pt`、`margin_top_mm`、`margin_right_mm`、`style` | 証拠番号スタンプの文字サイズ（既定16ポイント。［ファイル］→［オプション］で変えた大きさがあれば、そちらが使われます）・余白・見た目（既定は赤字） |
| `pdf` | `a4_mm`、`a3_mm`、`size_tolerance_mm` | 用紙寸法と判定の許容誤差 |
| `pii_detection` | `patterns` | 個人情報パターン検出の正規表現（追加・調整可能） |
| `logging` | `log_dir`、`level` | デバッグ用詳細ログの出力先とレベル |

各項目には、根拠とした一次資料（操作マニュアルの版数、準備の手引の版数等）がコメントとして記載されています。数値の意味や根拠を確認したい場合は、`config.yaml` 内のコメントを直接ご参照ください。

編集内容に誤りがある場合（正規表現の書き間違い、必要な項目の削除等）は、起動時にどこをどう直すべきかを示すエラーダイアログが表示されます。その場合は、メッセージに従って該当箇所を修正するか、配布時の `config.yaml` の内容に戻してください。

# 第6章 AIを使ってツールを改造するとき

本ツールはソースコードを同梱しており、事務所独自の機能をAI（コーディング支援のAI）で追加することもできます。その場合は、次の手順で、**AIが実データ（依頼者・事件の情報）に届かない場所で作業させてください。**

## 6.1 なぜ注意が必要か

AIが読んだファイルや画面は、AIの会社のサーバーに送られます。依頼者の情報をAIに読ませると、守秘義務の点で問題になり得ます。AIは作業の途中で、思わぬファイルを開くことがあります。そのため、「気をつけて使う」だけでは防げません。AIが実データに届かない場所で作業させてください。

## 6.2 手順1　AI専用のWindowsユーザーを作る

- ［設定］→［アカウント］→［他のユーザー］で、AIの作業に使うユーザーを作ります。管理者にはせず、標準ユーザーにします。
- このユーザーでは、事務所のOneDrive・SharePointにサインインしません。共有フォルダ・ネットワークドライブ・暗号化した仮想ドライブにもつなぎません。
- 作ったら、このユーザーでエクスプローラーを開き、事務所の共有データの場所が見えないこと、開けないことを確かめます。見える場合は、そのフォルダのアクセス許可からこのユーザーを外してください。
- 別のPCをAIの作業に使えるなら、さらに確実です。

## 6.3 手順2　このユーザーで、ソースと試用データだけを使って作業する

- ソースと試すデータは、このユーザーで新しく手に入れます。サイトから配布物（zip）をダウンロードし直し、`source/` フォルダのソースコードを使います（GitHubのVBA-Assets/VA_MINTSから取ってもかまいません）。ふだんのユーザーのフォルダから写さないでください。
- 設定ファイル（`config.yaml`）も、新しくダウンロードした配布物のものを使います。ふだん使っているものを写さないでください。
- 試すデータは、架空の文書か、付属のスクリプト（`source/scripts/generate_sample_folder.py`）で作る架空のサンプルファイルを使います。実際の証拠・書面は使いません。
- 実データの中身を、AIに貼り付けたり、画面の写しで見せたりしないでください。
- 不具合をAIに相談するときは、［ヘルプ］→［診断情報をコピー］（3.7参照）を使います。診断情報には、版・設定の数値・件数やエラーの場所だけが入り、ファイル名などの中身は入りません。

## 6.4 手順3　実データでの確認と入れ替えは、ふだんのユーザーで人が行う

- 改造してできた実行ファイル（`config.yaml` を変えた場合はそれも）を、ふだんのユーザーに移します。
- まず実データの写しを置いた試験用のフォルダで試し、問題がなければ使い始めます（本ツールは入力フォルダの原本を書き換えませんが、念のため写しで試してください）。
